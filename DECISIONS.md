### Integration contract for SmartOmni (09c)
1. Status table of a batch code (read with Get Coupon); every state other than "free" is final:

   | `status` | `usage_stats.redeemed_count` | Meaning | SmartOmni |
   |---|---|---|---|
   | `ONGOING` | 0 | Free, or handed out but not used yet | Keep polling if handed out |
   | `ONGOING` | 1 | Used in an order | Stop polling, mark used |
   | `DEACTIVATED` | 0 or 1 | Burned (UNPAID order cancelled, Q8) or switched off by the seller | Stop polling, never hand out again |
   | `EXPIRED` | 0 or 1 | Expired | Stop polling |
   | `NOT_START` | 0 | Not started yet | Do not hand out yet |

   The API cannot tell "burned" from "switched off" (the OAS only has `DEACTIVATED`).
2. Search has no `usage_stats` (OAS schema): use Get Coupon per code. Poll only codes handed out and not final; filter expired/deactivated codes in bulk with Search `status: ["EXPIRED", "DEACTIVATED"]`; after the first pull store `coupon_id` and call Get Coupon by id.
3. `status` stays `ONGOING` after the code is used: the OAS has no "used up" status, only `redeemed_count` goes 0 -> 1.
4. Orders carry no coupon id or code (Q10). Loyalty does not need it: points come from `sub_total` after discount; the discount is in `seller_discount` (Order Detail) and `subtotal_deduction_seller` (Price Detail). `voucher_deduction_seller` is a discount TYPE code in the OAS (`1010000`, ...), not an amount, so its current `'0'` does not distort any amount.
5. `title_keyword` is case-insensitive and "contains" (Q9).
6. `claimed_count` = `redeemed_count` (09a-7): the simulator has no claim concept; claiming happens in SmartOmni.
7. A `DEACTIVATED` code is refused at checkout with `coupon_deactivated`.
